# ESPHA — Waveshare ESP32-S3-Touch-AMOLED-1.43 в Home Assistant

Прошивка на [ESPHome](https://esphome.io) для круглого AMOLED-дисплея
**Waveshare ESP32-S3-Touch-AMOLED-1.43** (466×466, QSPI, ёмкостный тач).
Плата становится обычным устройством Home Assistant и показывает на экране
часы и любые ваши сущности.

Прошивается **прямо из браузера** — ничего устанавливать на компьютер не нужно.

---

## Прошить из браузера

1. Откройте **https://koshg28.github.io/ESPHA/** в Chrome, Edge или Opera
   (Safari и Firefox не поддерживают Web Serial; с телефона тоже не получится).
2. Подключите плату кабелем USB-C — обязательно с передачей данных.
3. Нажмите кнопку установки, выберите COM-порт (обычно `USB JTAG/serial debug unit`),
   затем **Install ESPHA**.
4. После записи там же в браузере введите имя и пароль Wi-Fi.
5. В Home Assistant откройте **Настройки → Устройства и службы** — устройство
   найдётся само. Нажмите «Настроить».

Если платы нет в списке портов: отключите кабель, зажмите кнопку **BOOT**,
подключите кабель, отпустите кнопку и повторите.

> Страница установщика публикуется на GitHub Pages при пуше в `main`.
> Чтобы она заработала в вашем форке, включите в репозитории
> **Settings → Pages → Source: GitHub Actions**.

## Прошить через ESPHome Builder (вариант без браузера)

1. Установите в Home Assistant надстройку **ESPHome Builder**.
2. Скопируйте в неё `espha.yaml` и папку `packages/`.
3. Добавьте свои `wifi:` и `api:` (или воспользуйтесь мастером «New device»).
4. Нажмите **Install → Plug into this computer**.

## Что на экране

Изображение повёрнуто на 90° по часовой стрелке — разъём USB-C оказывается
внизу. Четыре страницы, листаются свайпом влево-вправо или кнопкой **BOOT**:

| Страница | Что показывает |
| --- | --- |
| **Часы** | Крупное время, дата по-русски, два значения из Home Assistant, кольцо прогресса суток |
| **Дом** | Четыре плитки с числовыми сущностями |
| **Принтер** | Прогресс печати Bambu Lab: кольцо, проценты, статус, температуры сопла и стола, слой, остаток времени |
| **Устройство** | Wi-Fi, уровень сигнала, IP, время работы, регулятор яркости |

Время берётся из Home Assistant и записывается в часы реального времени
**PCF85063** на плате, поэтому после перезагрузки время остаётся верным даже
без сети.

## 3D-принтер Bambu Lab

Страница принтера берёт данные из интеграции
[Bambu Lab](https://github.com/greghesp/ha-bambulab) (ставится через HACS).
Она работает и в **LAN-режиме**, без облака — достаточно включить на принтере
«LAN Only Mode» и ввести код доступа с экрана принтера.

Имена сущностей задаются подстановками в `espha.yaml`. По умолчанию там `p1s` —
замените на имя своего принтера:

```yaml
substitutions:
  printer_progress_entity: sensor.p1s_print_progress
  printer_status_entity: sensor.p1s_print_status
  printer_nozzle_entity: sensor.p1s_nozzle_temperature
  printer_bed_entity: sensor.p1s_bed_temperature
  printer_layer_entity: sensor.p1s_current_layer
  printer_total_layers_entity: sensor.p1s_total_layer_count
  printer_remaining_entity: sensor.p1s_remaining_time
  printer_remaining_to_minutes: "60"
```

Точные `entity_id` смотрите в **Инструменты разработчика → Состояния**,
отфильтровав по имени принтера.

> **Про остаток времени.** Интеграция отдаёт `remaining_time` в минутах, но
> помечает его как «предпочтительно в часах», поэтому в Home Assistant сущность
> обычно оказывается **в часах**. Отсюда множитель `printer_remaining_to_minutes: "60"`.
> Если в Инструментах разработчика у сущности единица `min` — поставьте `"1"`.

Кольцо становится зелёным, когда статус печати `running`, и серым в остальных
состояниях. Названия статусов переведены на русский в
[`packages/printer.yaml`](packages/printer.yaml) — там же их можно поправить.

Иконки берутся из шрифта Material Design Icons, он скачивается при сборке.

## Сущности в Home Assistant

| Сущность | Назначение |
| --- | --- |
| `number.*_яркость_экрана` | Яркость AMOLED, 5–100 % |
| `number.*_яркость_в_режиме_ожидания` | Насколько гасить экран без касаний |
| `number.*_гасить_экран_через` | Задержка гашения, 0 = не гасить |
| `button.*_перезагрузка` | Перезагрузка платы |
| `binary_sensor.*_кнопка_boot` | Кнопка на плате |
| `sensor.*_уровень_wi_fi`, `*_время_работы`, `*_температура_чипа` | Диагностика |

## Поведение экрана

- **Индикатор страниц** живёт в `top_layer` LVGL, а каждая страница сообщает
  свой номер скриптом `mark_page` из триггера `on_load`.
- **Защита AMOLED.** Содержимое раз в `pixel_shift_interval` (по умолчанию
  3 минуты) сдвигается на два пикселя по кругу, чтобы статичные элементы не
  выжигали пиксели. В простое панель не просто гаснет, а возвращается на
  страницу часов — меньше горящих пикселей.
- **Живые часы.** Двоеточие мигает раз в секунду: без этого на экране совсем
  ничего не движется и панель выглядит зависшей.
- **Потеря связи с Home Assistant.** Значения на экране приглушаются, чтобы
  вчерашние данные не выдавались за свежие.
- **Печать закончилась или упала** — экран сам просыпается и показывает
  страницу принтера.

## Поворот изображения

Поворот задаётся в `packages/ui.yaml` в секции `lvgl:` как `rotation: 90`.
В конфиге дисплея его указывать нельзя — ESPHome это запрещает при
использовании LVGL.

Координаты тача LVGL при повороте **не** разворачивает, поэтому они
поворачиваются отдельно, в `packages/hardware.yaml`:

```yaml
transform:
  swap_xy: true
  mirror_x: false
  mirror_y: true
```

Панельная точка `(px, py)` переходит в логическую `(py, 465 - px)`: сначала
переставляются оси, затем зеркалится Y. Если поменяете угол поворота — эти
флаги нужно пересчитать, иначе касания поедут.

У контроллера CO5300 нет аппаратной перестановки осей, поэтому поворот на 90°
делается программно и стоит процессорного времени. Если интерфейс станет
заметно тормозить, разумные варианты — `rotation: 180` (зеркалирование по обеим
осям контроллер умеет сам) или отказ от поворота.

## Настроить свои данные

Всё настраивается подстановками в начале `espha.yaml`:

```yaml
substitutions:
  timezone: Europe/Moscow

  slot1_entity: sensor.outside_temperature   # entity_id из Home Assistant
  slot1_title: "На улице"                    # подпись на экране
  slot1_format: "%.1f°"                      # формат printf для значения
```

Слотов четыре (`slot1`…`slot4`). Слоты 1 и 2 показываются и на странице часов,
и на странице «Дом»; слоты 3 и 4 — только на «Доме».

Примеры форматов:

| Формат | Результат |
| --- | --- |
| `"%.1f°"` | `21.4°` |
| `"%.0f%%"` | `65%` |
| `"%.0f Вт"` | `840 Вт` |
| `"%.2f кВт·ч"` | `12.30 кВт·ч` |

После правки — **Install** в ESPHome Builder, обновление уйдёт по воздуху.

## Железо и распиновка

Плата: ESP32-S3R8, 8 МБ octal PSRAM, 16 МБ флеш. AMOLED 466×466 — Waveshare
называет контроллер **SH8601**, но на живом железе картинку даёт только драйвер
**CO5300**. Тачскрин **FT3168** по I2C, без линий RST и INT. Плюс акселерометр
QMI8658, часы PCF85063 и слот microSD.

| Сигнал | GPIO |
| --- | --- |
| Дисплей QSPI CS | 9 |
| Дисплей QSPI CLK | 10 |
| Дисплей QSPI D0 / D1 / D2 / D3 | 11 / 12 / 13 / 14 |
| Дисплей RESET | 21 |
| Питание панели (LCD EN, активно в 1) | 42 |
| I2C SDA / SCL (тач, IMU QMI8658, RTC PCF85063) | 47 / 48 |
| Тачскрин FT3168 | адрес `0x38`, RST и INT не разведены |
| Напряжение батареи (делитель 1.5x) | 4 |
| Кнопка BOOT | 0 |

Распиновка сверена со схемой Waveshare через проект
[ON6PH/capsule-radar-1.43](https://github.com/ON6PH/capsule-radar-1.43) —
там же подробный разбор железа этой платы.

Распиновка задана в [`packages/hardware.yaml`](packages/hardware.yaml).

> **Не перепутайте с 1.43C.** У Waveshare есть похожая, но совсем другая плата —
> **ESP32-S3-Touch-AMOLED-1.43C**: другой модуль (ESP32-S3-PICO-1-N8R8), нет IMU
> и RTC, зато есть кодек ES8311. У неё другие ноги дисплея
> (`D0=9, D1=10, D2=11, D3=12, CLK=14, CS=15, RESET=13`) и тач с `RST=16, INT=17`.
> Этот конфиг для неё не подойдёт.

`flash_size` указан как `8MB` намеренно: если на вашей плате 16 МБ, прошивка
всё равно встанет, просто часть флеша останется свободной. Хотите использовать
весь объём — поменяйте значение в `packages/hardware.yaml`.

## Структура репозитория

```
espha.yaml                 основной конфиг, он же пакет для «усыновления» в HA
espha-factory.yaml         то же самое + суффикс MAC в имени, собирается для браузера
packages/hardware.yaml     плата: дисплей, тач, I2C, SPI, кнопка
packages/screen.yaml       яркость AMOLED и автогашение
packages/entities.yaml     время, слоты Home Assistant, диагностика
packages/printer.yaml      данные 3D-принтера Bambu Lab
packages/ui.yaml           шрифты и интерфейс LVGL
packages/behaviour.yaml    индикатор страниц, защита от выгорания, живые часы
components/ft3168/         собственный драйвер тачскрина FT3168
static/index.html          страница установщика (ESP Web Tools)
.github/workflows/build.yml  сборка прошивки и публикация на GitHub Pages
```

## Если что-то не работает

**Экран чёрный, но устройство в сети.** Скорее всего у вас ревизия «C» —
см. блок про распиновку выше. Проверьте также, что в логах нет ошибок PSRAM:
без неё буфер 466×466 не выделится.

**Экран есть, тач не реагирует.** Так вело себя первое поколение этого конфига —
исправлено. Дело оказалось не в железе: на плате стоит **FT3168** по адресу
`0x38`, но ни один штатный драйвер ESPHome с ним не работает.

| Драйвер | Почему не подходит |
| --- | --- |
| `ft5x06` | Читает vendor ID из регистра `0xA8` и принимает только `0x51`, `0x11`, `0xCD`. На всё остальное вызывает `mark_failed()` и больше панель не опрашивает. |
| `cst816` | Карта регистров совпадает, но он читает 13 байт одним пакетом с адреса `0x00`, а FT3168 пакетное чтение не отдаёт. |

Поэтому в репозитории лежит собственный драйвер —
[`components/ft3168`](components/ft3168). Он повторяет логику родного
`Arduino_FT3x68` от Waveshare: при старте пишет `0x01` в регистр power mode
`0xA5` (без этого чип отвечает на адрес, но координат не отдаёт), затем читает
регистры `0x02`–`0x06` **по одному байту**.

Проверить, что чип на месте, можно по сущности **«Устройства на шине I2C»** в
Home Assistant — та же строка есть на странице «Устройство» на экране, её можно
пролистать кнопкой BOOT:

| Адрес | Что это |
| --- | --- |
| `0x38` | тачскрин FT3168 |
| `0x51` | часы PCF85063 |
| `0x6B` | акселерометр QMI8658 |

Если `0x38` в списке есть, а касания не работают — вопрос к драйверу, а не к
железу. Если `0x38` нет, а `0x51` и `0x6B` есть — вопрос к самому чипу тача.

**Касания будят экран, но страницы не листаются.** Пробуждение висит на триггере
`on_touch` самого драйвера тача, а жесты обрабатывает LVGL — и жест доходит до
виджета под пальцем, до корневого контейнера страницы не всплывая. Поэтому
листание считается на уровне драйвера: `on_update` запоминает смещение от точки
начала касания (`x_org`/`y_org`), а `on_release` сравнивает его с порогом
`swipe_threshold` из `espha.yaml` — по умолчанию 60 пикселей. Слишком
чувствительно или наоборот — поменяйте это число.

**Полоса по краю экрана.** Панель 466×466 живёт внутри контроллера на 480×480
со сдвигом; за это отвечает `offset_width: 6`. Если полоса всё же есть,
попробуйте значения 0 или 12.

**Нет логов по USB.** Плата использует встроенный USB-Serial/JTAG, поэтому в
`espha.yaml` стоит `logger: hardware_uart: USB_SERIAL_JTAG`. Если у вашей
ревизии стоит внешний USB-UART мост — уберите эту строку.
