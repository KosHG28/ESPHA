# Сервер радара для ESPHA

Маленький сервер на Python: берёт самолёты вокруг дома из FlightRadar24
(библиотека [FlightRadarAPI](https://github.com/JeanExtreme002/FlightRadarAPI))
и отдаёт их плате ESPHA для страницы «Радар». Заодно рисует для неё тёмную
карту с подписями городов и показывает в браузере веб-радар с картой.

| Адрес | Что отдаёт |
| --- | --- |
| `/` | Веб-радар с картой — открыть в браузере |
| `/esp?r=100` | Самолёты для платы: 40 ближних в радиусе ×1,6, уже в пикселях экрана |
| `/map.jpg?r=100` | Карта 466×466 под радиус r км: тёмные тайлы CartoDB, города по-русски |
| `/data` | Самолёты и осадки для веб-радара |
| `/health` | `ok`, если сервер жив |

Самый простой способ поставить — готовый стек для Dockge или Portainer, см.
ниже «Dockge, Portainer».

## Dockge, Portainer — без копирования файлов

В репозитории есть готовый стек [`dockge-compose.yml`](dockge-compose.yml):
1. В Dockge нажмите «+ Compose» и задайте имя стека, например `espha-radar`.
2. Вставьте туда весь файл целиком.
3. Поменяйте координаты дома и нажмите «Развернуть».

Файлы сервера скачиваются с GitHub при сборке — копировать ничего не нужно.

Порт на хосте в нём — **8088**: 8080 часто занят (qBittorrent). Тогда в
`espha.yaml`: `radar_url: "http://IP_ХОСТА:8088"`.

Чтобы подтянуть новую версию сервера, пересоберите стек. В консоли хоста:
`docker compose -f /opt/stacks/espha-radar/compose.yaml up -d --build --no-cache`.
Или в Dockge: остановить, удалить образ `espha-radar`, развернуть заново.

## Установка в Docker

Нужен компьютер или NAS с Docker, который всегда включён и в одной сети с
платой: домашний сервер, Raspberry Pi, Synology, машина с Home Assistant.

1. Скопируйте папку `server/radar` из репозитория на этот компьютер,
   например в `~/espha-radar`:
   ```sh
   git clone https://github.com/KosHG28/ESPHA.git
   cp -r ESPHA/server/radar ~/espha-radar
   cd ~/espha-radar
   ```
2. Впишите координаты дома в `docker-compose.yml` — `CENTER_LAT` и
   `CENTER_LON` (по умолчанию центр Москвы).
3. Соберите и запустите:
   ```sh
   docker compose up -d --build
   ```
4. Проверьте в браузере на любом компьютере в сети:
   - `http://АДРЕС_СЕРВЕРА:8080/` — веб-радар с самолётами;
   - `http://АДРЕС_СЕРВЕРА:8080/map.jpg?r=100` — карта для платы. Первый раз
     она собирается несколько секунд: качаются тайлы, потом берутся из кэша
     в `./data`.
5. В `espha.yaml` впишите адрес сервера:
   ```yaml
   radar_url: "http://192.168.1.10:8080"
   ```
   и обновите прошивку.
6. В Home Assistant включите **«Страница радара»** — на плате появится пятая
   страница.

Журнал сервера: `docker compose logs -f`. Обновить после правок:
`docker compose up -d --build`.

### Без docker compose

```sh
docker build -t espha-radar .
docker run -d --name espha-radar --restart unless-stopped -p 8080:8080 \
  -e CENTER_LAT=55.7558 -e CENTER_LON=37.6173 -v "$PWD/data:/data" espha-radar
```

### Portainer / Synology

Создайте стек (Stack) из `docker-compose.yml`. Так как образ собирается из
`Dockerfile`, папку `radar` нужно положить на диск NAS и указать её как
каталог сборки. Порт 8080 можно поменять: `"8090:8080"` — тогда и в
`radar_url` порт 8090.

## Настройки

Переменные окружения в `docker-compose.yml`:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `CENTER_LAT`, `CENTER_LON` | центр Москвы | Центр радара — дом |
| `PORT` | `8080` | Порт внутри контейнера |
| `MAP_BRIGHTNESS` | `1.15` | Яркость карты: 1.0 — как у CartoDB |
| `CITIES_FILE` | `cities.json` | Список городов для подписей |
| `TILE_URL` | CartoDB dark без подписей | Откуда брать тайлы карты |
| `CACHE_DIR` | `/data` | Кэш тайлов и готовых карт |

**Города** — `cities.json`: название и координаты. На карте подписываются
те, что попадают в круг, ближние к дому — в первую очередь, без наложений.
У четырёх городов стоит `"weather": true` — по ним веб-радар показывает
осадки. После правки списка удалите `data/maps` и перезапустите контейнер.

## Заметки

- Самолёты запрашиваются у FlightRadar24 не чаще раза в 6 секунд, сколько
  бы клиентов ни спрашивало, и в радиусе 300 км (×1,5). Плата и браузер
  берут из этого же кэша.
- Положения на плате считаются в той же проекции (веб-Меркатор), что и
  карта, — самолёты летят ровно над картой при любом радиусе.
- Библиотека FlightRadarAPI неофициальная: FlightRadar24 может её
  временно блокировать. Тогда плата пишет «Нет связи с сервером радара», а
  сервер в журнале — «Ошибка FlightRadar24».
- В новых версиях библиотеки модуль называется `FlightRadarAPI`, в старых —
  `FlightRadar24`. Сервер понимает оба.
- Карта — тайлы © CARTO, данные © участники OpenStreetMap.
