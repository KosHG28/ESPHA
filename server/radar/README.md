# Сервер радара для ESPHA

Маленький сервер на Python: берёт самолёты вокруг дома из FlightRadar24
(библиотека [FlightRadarAPI](https://github.com/JeanExtreme002/FlightRadarAPI))
и отдаёт их плате ESPHA для страницы «Радар». Заодно рисует для неё тёмную
карту с подписями городов и показывает в браузере веб-радар с картой.

| Адрес | Что отдаёт |
| --- | --- |
| `/` | Веб-радар с картой — открыть в браузере |
| `/esp?r=100` | Самолёты для платы: 40 ближних в радиусе ×1,6, уже в пикселях экрана |
| `/map.jpg?r=100` | Карта 466×466 под радиус r км: тёмная карта, города по-русски. `&s=sat` — другой стиль |
| `/tile/<стиль>/z/x/y` | Тайлы для веб-радара — через сервер и его кэш |
| `/logo/AFL.png` | Логотип авиакомпании по коду ИКАО — через сервер и его кэш |
| `/data` | Самолёты для веб-радара |
| `/flight?f=SU1520` | Отслеживаемый рейс для платы: аэропорты, дуга маршрута в пикселях экрана, самолёт, время |
| `/trackmap.jpg?v=…` | Карта маршрута рейса, повёрнутая так, что вылет слева |
| `/health` | `ok`, если сервер жив |

Самый простой способ поставить — готовый стек для Dockge или Portainer, см.
ниже «Dockge, Portainer».

## Dockge, Portainer — без копирования файлов

В репозитории есть готовый стек [`dockge-compose.yml`](dockge-compose.yml):
1. В Dockge нажмите «+ Compose» и задайте имя стека, например `espha-radar`.
2. Вставьте туда весь файл целиком.
3. В поле **«.env»** (в Dockge оно под compose) впишите координаты дома:
   ```
   CENTER_LAT=55.7558
   CENTER_LON=37.6173
   ```
   Так они остаются только у вас на сервере и не попадают в GitHub, даже
   если вы где-то выложите свой compose.
4. Нажмите «Развернуть».

Файлы сервера скачиваются с GitHub при сборке — копировать ничего не нужно.

Порт на хосте в нём — **8088**: 8080 часто занят (qBittorrent). Тогда в
Home Assistant у платы впишите **«Адрес сервера радара»** —
`http://IP_ХОСТА:8088`.

Чтобы подтянуть новую версию сервера, пересоберите стек. В консоли хоста:
`docker compose -f /opt/stacks/espha-radar/compose.yaml up -d --build --no-cache`.
Или в Dockge: остановить, удалить образ `espha-radar`, развернуть заново.

## Установка в Docker

Нужен компьютер или NAS с Docker, который всегда включён и в одной сети с
платой: домашний сервер, Raspberry Pi, Synology, машина с Home Assistant.

1. Скопируйте папку `server/radar` из репозитория на этот компьютер,
   например в `~/espha-radar`:
   ```sh
   git clone https://github.com/KosHG28/ESPHA.git
   cp -r ESPHA/server/radar ~/espha-radar
   cd ~/espha-radar
   ```
2. Рядом с `docker-compose.yml` создайте файл `.env` с координатами дома:
   ```
   CENTER_LAT=55.7558
   CENTER_LON=37.6173
   ```
3. Соберите и запустите:
   ```sh
   docker compose up -d --build
   ```
4. Проверьте в браузере на любом компьютере в сети:
   - `http://АДРЕС_СЕРВЕРА:8080/` — веб-радар с самолётами;
   - `http://АДРЕС_СЕРВЕРА:8080/map.jpg?r=100` — карта для платы. Первый раз
     она собирается несколько секунд: качаются тайлы, потом берутся из кэша
     в `./data`.
5. В Home Assistant у платы (Настройки → Устройства → ESPHA, раздел
   «Конфигурация») впишите **«Адрес сервера радара»**, например
   `http://192.168.1.10:8080`. Перепрошивать не нужно — адрес запоминается.
   Своя сборка прошивки может задать адрес по умолчанию: `radar_url` в
   `espha.yaml`.
6. В Home Assistant включите **«Страница радара»** — на плате появится пятая
   страница.

Журнал сервера: `docker compose logs -f`. Обновить после правок:
`docker compose up -d --build`.

### Без docker compose

```sh
docker build -t espha-radar .
docker run -d --name espha-radar --restart unless-stopped -p 8080:8080 \
  --env-file .env -v "$PWD/data:/data" espha-radar
```

### Portainer / Synology

Создайте стек (Stack) из `docker-compose.yml`. Так как образ собирается из
`Dockerfile`, папку `radar` нужно положить на диск NAS и указать её как
каталог сборки. Порт 8080 можно поменять: `"8090:8080"` — тогда и в
«Адресе сервера радара» порт 8090.

## Настройки

Переменные окружения в `docker-compose.yml`:

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `CENTER_LAT`, `CENTER_LON` | центр Москвы | Центр радара — дом. Задаются в `.env` |
| `PORT` | `8080` | Порт внутри контейнера |
| `MAP_STYLE` | `dark` | Карта платы, см. ниже «Стили карты» |
| `MAP_BRIGHTNESS` | `1.15` | Яркость карты: 1.0 — как у источника |
| `CITIES_FILE` | `data/cities.json` | Свой список городов вместо OpenStreetMap |
| `TILE_URL` | — | Свой источник тайлов `…/{z}/{x}/{y}.png` вместо `MAP_STYLE` |
| `CACHE_DIR` | `/data` | Кэш тайлов и готовых карт |

**Города** сервер при первом запуске сам берёт из OpenStreetMap (Overpass
API, без ключа): все города и посёлки в 450 км от дома, с численностью.
Это занимает до пары минут и делается один раз — список ложится в `data/`.
Пока его нет, подписываются крупные города России из `cities.json`.
Подписи без наложений, крупные — в первую очередь.

Свой список — `data/cities.json` в том же виде, что `cities.json`
(название, `lat`, `lon`; кто выше в списке — того подписывают первым).
После правки удалите `data/maps` и перезапустите контейнер.

### Вид радара — с веб-страницы

Всё, что на веб-странице, действует и на плату: она получает настройки
вместе с самолётами и применяет их за 8 секунд.

| На странице | На плате |
| --- | --- |
| Масштаб | Радиус, с которого открывается радар; свайп на часах меняет его на ходу |
| Базовый слой | Стиль карты — плата скачает новую |
| Метки и маршруты | Подписи `SVO-KUF` у самолётов |
| Сетка и компас | Кольца с километрами и стороны света |
| Цвет по высоте | Иначе все самолёты янтарные |
| Форма силуэтов | Иначе одна стрелка по курсу |
| Отметки за кругом | Красные точки на ободе |
| Сколько самолётов | 5, 10, 20 или 40 ближних |

Настройки хранятся в `data/config.json` и переживают перезапуск.
`MAP_STYLE` задаёт стиль только до первой правки на странице.

### Стили карты

Все — без ключей API и регистрации:

| `MAP_STYLE` | Что это |
| --- | --- |
| `dark` | Тёмно-серая карта Esri без подписей — по умолчанию |
| `sat` | Спутниковые снимки Esri, притемнённые под самолёты |
| `osm-dark` | OpenStreetMap, перекрашенная в тёмно-синие тона |
| `osm` | Обычная светлая OpenStreetMap |

Если тайлы стиля не скачиваются, сервер сам соберёт карту из `osm-dark`
(до перезапуска) и напишет об этом в журнал. Веб-радар переключает те же
стили в списке «Базовый навигационный слой».

CartoDB больше не используется: он стал требовать ключ API и рисует на
карте «API KEY REQUIRED». Если карта осталась с этой надписью — удалите
папку `data` стека (кэш) и перезапустите.

## Заметки

- Самолёты запрашиваются у FlightRadar24 не чаще раза в 6 секунд, сколько
  бы клиентов ни спрашивало, и в радиусе 300 км (×1,5). Плата и браузер
  берут из этого же кэша.
- Положения на плате считаются в той же проекции (веб-Меркатор), что и
  карта, — самолёты летят ровно над картой при любом радиусе.
- Библиотека FlightRadarAPI неофициальная: FlightRadar24 может её
  временно блокировать. Тогда плата пишет «Нет связи с сервером радара», а
  сервер в журнале — «Ошибка FlightRadar24».
- В новых версиях библиотеки модуль называется `FlightRadarAPI`, в старых —
  `FlightRadar24`. Сервер понимает оба.
- Логотипы авиакомпаний на веб-радаре — из набора
  [airline-logos](https://github.com/sexym0nk3y/airline-logos). Сервер качает
  каждый один раз и хранит в `data/logos`; каких нет в наборе — запоминает и
  переспрашивает раз в неделю. Свой источник — `LOGO_URL` с `{icao}`.
- Карта — тайлы © Esri (Esri, HERE, Garmin, Maxar и др.) и © участники
  OpenStreetMap.
